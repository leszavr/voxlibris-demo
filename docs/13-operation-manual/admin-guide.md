# Инструкция по эксплуатации платформы VoxLibris для администраторов

**Статус:** Current  
**Дата обновления:** 2026-11-21  
**Версия:** 1.0

Эта инструкция описывает ежедневное управление VoxLibris через административную панель: пользователей, книги, клубы, жалобы, записи эфиров, тарифы, подписки, настройки и данные. Она рассчитана на администраторов и модераторов платформы.

> Инструкция описывает работу через интерфейс. Технические операции с сервером, базой данных и файлами вынесены в отдельный раздел и выполняются только по согласованной процедуре.

## 1. Роли и зоны ответственности

В VoxLibris есть две плоскости ролей, которые не нужно путать:

1. **Платформенные роли** — доступ к административной панели и управлению всей платформой.
2. **Роли внутри клуба** — владелец, модератор и участник конкретного клуба.

Эта инструкция посвящена платформенным ролям. Управление клубами со стороны пользователей описано в пользовательской инструкции.

### 1.1. Платформенные роли

| Роль | Что может | Чего не может |
|---|---|---|
| **Пользователь** | Читать, создавать клубы, загружать книги, общаться, оформлять подписки | Заходить в административную панель |
| **Модератор** | Открывать административную панель и работать с записями эфиров: прослушивать, скачивать, одобрять и отклонять | Управлять пользователями, книгами, клубами, жалобами, тарифами, подписками, настройками и аудитом; удалять записи; назначать роли |
| **Администратор** | Все разделы панели: пользователи, книги, жанры, клубы, жалобы, аналитика, KPI, аудит, геймификация, записи эфиров, платежи, тарифы, подписки, финансовый аудит, настройки | — |

### 1.2. Права по разделам

| Раздел | Администратор | Модератор |
|---|---|---|
| Панель управления | Да | Нет |
| Пользователи | Да | Нет |
| Книги и гостевые книги | Да | Нет |
| Жанры | Да | Нет |
| Клубы | Да | Нет |
| Жалобы | Да | Нет |
| Аналитика и KPI | Да | Нет |
| Аудит | Да | Нет |
| Геймификация | Да | Нет |
| Записи эфиров: просмотр, прослушивание, скачивание, одобрение, отклонение | Да | Да |
| Записи эфиров: удаление | Да | Нет |
| Платежи, тарифы, подписки, финансовый аудит | Да | Нет |
| Настройки платформы | Да | Нет |

### 1.3. Важное ограничение интерфейса

Модератор может видеть в боковом меню разделы, которые ему недоступны. При открытии такого раздела или попытке сохранить изменение сервер вернёт отказ. Это нормальная защита. Если действие отклонено, для него нужна роль **администратора**.

Далее инструкция описывает действия администратора. Если вы модератор, ваш рабочий раздел — **«Записи эфиров»**; остальные разделы требуют администратора.

### 1.4. Кто назначает первого администратора

Первый администратор создаётся на стороне эксплуатации: его роль устанавливается в базе данных по согласованной процедуре. После этого все дальнейшие назначения выполняются в панели через раздел **«Пользователи»**.

Не просите пользователей «выдать себе админку» через интерфейс: обычный пользователь не может повысить себе роль.

## 2. Вход в административную панель

1. Войдите на платформу под аккаунтом администратора или модератора.
2. Откройте меню профиля.
3. Выберите **«Административная панель»**.
4. Если пункт не отображается, у аккаунта нет платформенной роли.

Адрес панели — `/admin`. При открытии раздела без прав платформа покажет отказ.

### 2.1. Безопасность входа

- Используйте отдельный пароль для административного аккаунта.
- Не передавайте учётные данные в мессенджерах и письмах.
- Выходите из панели на чужих устройствах.
- Если в настройках включён таймаут административной сессии, панель потребует повторного входа.
- Включение имперсонации и срок хранения журналов настраиваются в разделе **«Аудит» → «Настройки безопасности»**.

## 3. Обзор панели

Слева расположено меню разделов:

- **«Панель управления»** — сводка по платформе;
- **«Пользователи»** — аккаунты, роли, статусы;
- **«Книги»** — общая библиотека и гостевые книги;
- **«Жанры»** — справочник жанров;
- **«Клубы»** — все клубы платформы;
- **«Жалобы»** — единый центр жалоб;
- **«Аналитика»** — события, устройства, активность;
- **«KPI Метрики»** — эффективность проекта;
- **«Аудит»** — журнал действий администраторов;
- **«Геймификация»** — достижения, условия, награды;
- **«Записи эфиров»** — библиотека записей и модерация;
- **«Платежи»** — подключение платёжного провайдера;
- **«Конструктор тарифов»** — продукты, цены и права;
- **«Подписки»** — доступы пользователей;
- **«Финансовый аудит»** — платежи, заказы, начисления, расхождения;
- **«Настройки»** — общие, security, SMTP, обратная связь, функции, ЛС, мониторинг.

На мобильном устройстве меню открывается кнопкой в верхней части панели.

## 4. Панель управления

Раздел **«Панель управления»** показывает сводку:

- пользователи: всего, активные, ожидающие, заблокированные, администраторы, модераторы;
- книги: всего, активные, заблокированные;
- клубы: всего, активные, набор, завершённые, архив;
- время формирования отчёта.

Ниже расположены карточки распределения статусов и быстрые действия. Используйте раздел для ежедневной проверки: нет ли всплеска блокировок, зависших заявок или пустых клубов.

Если данные не загрузились, обновите страницу. Если ошибка повторяется, проверьте доступность базы данных в разделе **«Настройки» → «Мониторинг системы»**.

## 5. Пользователи

Раздел **«Пользователи»** — основной инструмент управления доступом.

### 5.1. Поиск и фильтры

Доступны:

- поиск по имени, email или идентификатору;
- фильтр по роли;
- фильтр по статусу;
- сортировка;
- переключение между активными и удалёнными пользователями.

### 5.2. Статусы пользователей

- **Ожидает активации** — аккаунт создан, но не активирован.
- **Активный** — полноценный доступ.
- **Заблокирован** — вход ограничен на срок или бессрочно.
- **Удалён** — аккаунт скрыт, но может быть восстановлен.

### 5.3. Действия с пользователем

В меню действий доступны:

- **«Активировать»** — для ожидающих аккаунтов.
- **«Сделать администратором»** — выдать полный доступ.
- **«Сделать модератором»** — выдать доступ к модерации.
- **«Сделать пользователем»** — снять платформенную роль.
- **«Выдать ПРО-чтеца»** или **«Отозвать ПРО-чтеца»** — право создавать клубы чтецов.
- **«Редактировать»** — изменить критические поля профиля.
- **«Сбросить пароль»** — отправить пользователю сброс.
- **«Отправить тестовый push»** — проверить push-канал.
- **«Зайти как...»** — имперсонация для диагностики.
- **«Удалить»** — мягкое удаление.
- **«Восстановить»** — вернуть удалённый аккаунт.
- **«Удалить окончательно»** — необратимое удаление.

### 5.4. Назначение прав

1. Найдите пользователя.
2. Откройте меню действий.
3. Выберите нужную роль.
4. Подтвердите действие.

Правила:

- назначать роли может только **администратор**;
- модератор не может повысить себя или другого пользователя;
- перед повышением проверьте, что аккаунт активен и принадлежит нужному человеку;
- не выдавайте администратора «на время»: используйте модератора;
- после увольнения сотрудника сразу снимайте роль и блокируйте аккаунт.

### 5.5. Блокировка и ограничения

При блокировке укажите причину и, если нужно, срок. Причина помогает при разборе жалоб и апелляций.

Для клубов чтецов доступны ограничения:

- запрет писать сообщения;
- ограничение доступа к клубу на срок;
- снятие ограничения.

### 5.6. Имперсонация

**«Зайти как...»** позволяет увидеть платформу глазами пользователя. Используйте только для диагностики и только при включённой имперсонации.

Правила:

- обязательно указывайте причину;
- не выполняйте от имени пользователя действия, которые он не просил;
- выходите из имперсонации сразу после проверки;
- все имперсонации фиксируются в аудите.

### 5.7. Удаление и восстановление

- **«Удалить»** скрывает аккаунт и связанные данные из обычных списков.
- **«Восстановить»** возвращает аккаунт.
- **«Удалить окончательно»** необратимо удаляет аккаунт и данные. Используйте только по регламенту и после подтверждения.

Перед окончательным удалением проверьте:

- нет ли активных подписок и платежей;
- нет ли открытых жалоб;
- нет ли клубов, где пользователь владелец;
- нет ли записей эфиров, которые нужно сохранить.

### 5.8. Удалённые пользователи

Отдельный режим показывает удалённые аккаунты. Здесь можно восстановить пользователя или удалить его окончательно.

## 6. Книги

Раздел **«Книги»** содержит две зоны:

1. **Общая библиотека** — книги пользователей и клубов.
2. **«Гостевые книги»** — книги, загруженные в гостевом режиме.

### 6.1. Общая библиотека

Сводка показывает:

- всего книг;
- активные;
- на модерации;
- заблокированные.

Фильтры:

- поиск по названию, автору или ISBN;
- статус: активные, на модерации, заблокированные;
- жанр.

### 6.2. Действия с книгой

В меню книги доступны:

- **«Скачать для проверки»** — получить файл;
- **«Одобрить»** — для книги на модерации;
- **«Заблокировать»** — с обязательной причиной;
- **«Разблокировать»** — вернуть доступ;
- **«Удалить»** — необратимо удалить книгу.

При блокировке:

1. Нажмите **«Заблокировать»**.
2. Укажите причину: нарушение авторских прав, запрещённый контент, нарушение закона и т.п.
3. Подтвердите.

Для пользовательских книг может отправляться email-уведомление. Формулируйте причину нейтрально и по факту.

### 6.3. Гостевые книги

Гостевые книги — отдельный контент. Они не смешиваются с общей библиотекой.

Доступны:

- поиск по названию, автору или коду гостя;
- фильтр по статусу: ожидают проверки, разрешены, заблокированы;
- просмотр кода гостя и даты загрузки;
- **«Скачать»**;
- **«Разрешить»**;
- **«Заблокировать»**;
- **«Удалить»**.

Гостевая книга доступна гостю сразу после загрузки, но при блокировке чтение закрывается. Если гость загрузил повторно такую же или похожую книгу, платформа может показать предупреждение о ранее заблокированном файле.

### 6.4. Правила модерации книг

- Проверяйте обложку, название, автора и содержимое.
- Не одобряйте книги с признаками пиратства, экстремизма, вредоносного контента.
- При сомнении запросите второе мнение.
- Причину блокировки сохраняйте так, чтобы её можно было объяснить пользователю.
- Не удаляйте книгу, если достаточно блокировки: удаление необратимо.

## 7. Жанры

Раздел **«Жанры»** — справочник, который используется в библиотеке, профиле, рекомендациях и фильтрах.

### 7.1. Список жанров

Доступны:

- поиск по коду или названию;
- список жанров;
- создание нового жанра;
- редактирование;
- удаление.

### 7.2. Поля жанра

- **«Код»** — техническое имя, уникальное;
- **«Название RU»** — отображаемое название на русском;
- **«Название EN»** — название на английском;
- **«Группа»** — объединение жанров;
- **«Порядок»** — порядок вывода;
- **«Алиасы»** — альтернативные названия через запятую;
- **«Описание»** — пояснение.

### 7.3. Как добавить жанр

1. Откройте **«Жанры»**.
2. Нажмите **«Новый»**.
3. Заполните код и название.
4. При необходимости добавьте группу, алиасы и описание.
5. Укажите порядок.
6. Нажмите **«Сохранить»**.

Требования:

- код не должен повторяться;
- код лучше писать латиницей, без пробелов;
- алиасы помогают распознавать книги с разными названиями жанра;
- не удаляйте жанр, если он используется в книгах, — сначала замените его.

Создание и изменение жанров доступно только администратору.

## 8. Клубы

Раздел **«Клубы»** показывает все клубы платформы, включая обычные клубы и клубы чтецов.

### 8.1. Поиск и фильтры

- поиск по названию;
- фильтр по статусу;
- фильтр по типу;
- сортировка.

### 8.2. Статусы клубов

- **Набор** — клуб набирает участников.
- **Активен** — клуб работает.
- **Завершён** — чтение завершено.
- **Архив** — клуб скрыт из активной работы.
- **На модерации** — клуб ожидает проверки.

### 8.3. Действия с клубом

В меню клуба доступны:

- **«Открыть клуб»** — посмотреть страницу;
- **«Сделать приватным»** или **«Сделать публичным»**;
- **«Одобрить клуб»** — для клубов на модерации;
- **«Отклонить клуб»** — с причиной;
- **«Изменить лимит участников»**;
- **«Передать владельца»**;
- **«Отправить на модерацию»**;
- **«Активировать»**;
- **«Завершить»**;
- **«В архив»** или возврат из архива;
- **«Удалить»**.

### 8.4. Модерация клуба

1. Откройте клуб.
2. Проверьте название, описание, обложку, книгу и правила.
3. Если всё в порядке — **«Одобрить клуб»**.
4. Если есть нарушения — **«Отклонить клуб»** и укажите причину.

Причина отклонения должна быть понятной владельцу: что именно нарушено и что нужно исправить.

### 8.5. Передача владельца

Используйте, если владелец потерял доступ или просит передать клуб. Выберите нового владельца из участников клуба. После передачи прежний владелец остаётся участником, если не выйдет.

### 8.6. Лимит участников

Лимит влияет на возможность приглашать новых участников. Не уменьшайте лимит ниже текущего числа участников без необходимости: это создаст конфликт.

### 8.7. Удаление клуба

Удаление клуба необратимо. Перед удалением проверьте:

- есть ли активные участники;
- есть ли текущая книга и обсуждения;
- есть ли платежи и подписки, связанные с клубом;
- нет ли открытых жалоб.

Если клуб нужно просто скрыть, используйте архив или приватность.

## 9. Жалобы и модерация

Раздел **«Жалобы»** собирает обращения по пользователям, клубам, книгам, чатам и личным сообщениям.

### 9.1. Типы жалоб

- на пользователя;
- на клуб;
- на книгу;
- на сообщение в чате;
- на личное сообщение.

### 9.2. Статусы

- **Новая** — жалоба ожидает разбора.
- **В работе** — взята модератором.
- **Решена** — приняты меры.
- **Отклонена** — нарушение не подтверждено.

Для жалоб на личные сообщения используются статусы:

- **Ожидает обработки**;
- **Проверена**;
- **Отклонена**.

### 9.3. Как обработать жалобу

1. Откройте жалобу.
2. Изучите описание и контекст.
3. При необходимости откройте переписку. Для этого обязательно укажите **причину просмотра**.
4. Примите решение:
   - **«Взять в работу»**;
   - **«Решить»**;
   - **«Отклонить»**.
5. Зафиксируйте меры: предупреждение, ограничение, блокировка, удаление контента.

### 9.4. Просмотр личных сообщений

Просмотр переписки — чувствительная операция. Она доступна только администратору и разрешена только:

- при наличии жалобы;
- с указанием причины;
- в объёме, необходимом для проверки.

Не копируйте переписку, не передавайте её третьим лицам и не используйте в личных целях. Все просмотры фиксируются.

### 9.5. Единые правила

- Соблюдайте нейтральность.
- Опирайтесь на правила платформы, а не на личные предпочтения.
- Не удаляйте контент без причины.
- При конфликте интересов передайте жалобу другому модератору.
- Сложные случаи эскалируйте администратору.

## 19. Настройки платформы

Раздел **«Системные настройки»** содержит несколько блоков. Изменять настройки может только администратор. Модератор может видеть часть разделов, но сохранение будет отклонено сервером.

### 19.1. Общие настройки

- **«Регистрация открыта»** — разрешить создание новых аккаунтов.
- **«Режим обслуживания»** — закрыть интерфейс для всех, кроме администраторов.
- **«Причина остановки»** — краткое описание.
- **«Ориентировочное время окончания»** — когда планируется завершение.
- **«Дополнительное сообщение»** — текст для пользователей.

После изменения нажмите **«Сохранить изменения»**.

Перед включением режима обслуживания предупредите пользователей и проверьте, что администраторы смогут войти.

### 19.2. Canonical URL

Поле **«Canonical URL»** задаёт основной адрес платформы для писем и внешних ссылок. Для каждого окружения (например, тестового и production) адрес задаётся отдельно.

Проверьте, что адрес:

- начинается с `https://`;
- не содержит лишнего пути;
- соответствует домену, на котором работает платформа.

После сохранения отправьте тестовое письмо и проверьте ссылку.

### 19.3. Настройки безопасности

- **«Макс. попыток входа»** — число неверных попыток за 15 минут до временной блокировки;
- **«Мин. длина пароля»** — применяется к регистрации, смене и сбросу;
- **«Требовать подтверждение email»** — новые пользователи должны подтвердить email;
- **«2FA для администраторов»** — пока недоступно, переключатель отключён.

Рекомендации:

- не снижайте минимальную длину пароля ниже 8;
- не увеличивайте число попыток выше 10 без необходимости;
- подтверждение email лучше держать включённым.

### 19.4. SMTP

Блок **«Настройки SMTP сервера»**:

- **«Включить SMTP»**;
- **«Хост SMTP сервера»**;
- **«Порт»**;
- **«Имя пользователя»**;
- **«Пароль»**;
- **«От кого (From email)»**;
- **«Использовать SSL/TLS»**.

После сохранения используйте **«Тестовая отправка»**:

1. Введите email.
2. Нажмите **«Отправить»**.
3. Проверьте письмо и папку «Спам».

Если письма не уходят, проверьте DNS-записи (SPF, DKIM, DMARC) в блоке **«Настройка DNS записей»** и обратитесь к почтовому провайдеру.

### 19.5. Обратная связь

Поле **«Email адреса для получения обратной связи»** принимает несколько адресов через запятую. На них приходят сообщения из формы обратной связи.

Проверьте, что адреса существуют и что на них не настроены жёсткие фильтры.

### 19.6. Функции платформы

Доступны переключатели:

- **«Включить гостевой режим»** — разрешить чтение без регистрации;
- **«Секция клубов чтецов на лендинге»**;
- **«Секция рейтинга чтецов на лендинге»**.

Если гостевой режим включён, пользователи могут открыть `/guest/library`. Если выключен, раздел недоступен.

Не включайте гостевой режим, если не готовы модерировать гостевые книги.

### 19.7. Самоочистка личных сообщений

- **«Максимальный срок хранения (дни)»** — от 10 до 365;
- **«Период до полного удаления (дни)»** — после мягкого удаления;
- **«Размер батча»** для форс-запуска.

Автоматическая задача запускается ежедневно. Кнопка **«Запустить очистку сейчас»** запускает очистку вручную.

Правила:

- не уменьшайте срок хранения без предупреждения пользователей;
- перед изменением политики согласуйте её с юридическими требованиями;
- форс-запуск используйте только при необходимости.

### 19.8. Мониторинг системы

Блок показывает:

- статус базы данных;
- статус сервера;
- статус сервисов;
- время проверки.

Если статус не «в норме», проверьте доступность инфраструктуры и обратитесь к эксплуатации.

## 20. Как добавлять сущности и данные

Ниже — краткие сценарии для типовых задач.

### 20.1. Добавить жанр

1. **«Жанры»** → **«Новый»**.
2. Заполнить код, название RU/EN, группу, порядок, алиасы, описание.
3. Сохранить.
4. Проверить, что жанр появился в фильтрах библиотеки и в профиле.

### 20.2. Добавить тариф

1. **«Конструктор тарифов»** → создать тариф.
2. Заполнить название, код, тип, область, статус, видимость.
3. Добавить цену.
4. Добавить права.
5. Проверить предпросмотр.
6. Сделать тариф активным и публичным.
7. Проверить страницу `/pricing`.

### 20.3. Добавить право доступа

1. Открыть **«Реестр прав»**.
2. Создать право: ключ, название, категория, тип значения, значение по умолчанию.
3. Сохранить.
4. Привязать право к тарифу в редакторе тарифа.
5. Проверить, что право появляется у пользователя после оплаты или ручной выдачи.

### 20.4. Добавить достижение

1. **«Геймификация»** → **«Достижения»**.
2. Создать достижение.
3. Указать название, описание, условие, награду, статус.
4. Сохранить.
5. При необходимости запустить пересчёт.

### 20.5. Добавить награду

1. **«Геймификация»** → **«Галерея»**.
2. Загрузить ассет или использовать массовый импорт.
3. Указать название, группу, теги, тип.
4. Сохранить.
5. Привязать награду к достижению.

### 20.6. Добавить книгу

Книги обычно загружают пользователи. Администратор может:

- одобрить книгу;
- заблокировать с причиной;
- удалить книгу;
- скачать файл для проверки.

Администратор не создаёт книгу за пользователя через панель. Если книга нужна платформе, её загружает пользователь с соответствующими правами.

### 20.7. Добавить клуб

Клубы создают пользователи. Администратор может:

- одобрить клуб;
- отклонить клуб;
- изменить лимит участников;
- изменить приватность;
- передать владельца;
- активировать, завершить или отправить в архив;
- удалить клуб.

### 20.8. Добавить пользователя

Пользователи создаются через регистрацию или приглашение. Администратор может:

- активировать;
- назначить роль;
- выдать ПРО-чтеца;
- заблокировать;
- восстановить;
- удалить.

Создавать пользователей вручную через панель не требуется.

### 20.9. Добавить запись эфира

Записи создаются автоматически после эфиров в Studio. Администратор:

- проверяет запись;
- одобряет или отклоняет;
- удаляет при необходимости.

### 20.10. Добавить гостевую книгу

Гостевые книги загружают гости. Администратор:

- проверяет;
- разрешает;
- блокирует;
- удаляет.

## 21. Переменные окружения и инфраструктура

Часть параметров задаётся не в панели, а в окружении приложения. Они не предназначены для изменения через интерфейс.

### 21.1. Где задаются

- локально — в файле `.env`;
- на сервере — в панели деплоя (например, CapRover) в переменных приложения;
- для клиентской сборки — переменные с префиксом `VITE_`.

После изменения переменных требуется перезапуск или повторная сборка приложения.

### 21.2. Основные переменные

| Переменная | Назначение |
|---|---|
| `NODE_ENV` | Режим работы: development, production, staging |
| `DATABASE_URL` | Подключение к PostgreSQL |
| `JWT_SECRET` | Секрет для access-токенов |
| `JWT_REFRESH_SECRET` | Секрет для refresh-токенов |
| `SESSION_SECRET` | Секрет сессий |
| `MASTER_KEY` | Ключ шифрования чувствительных данных |
| `S3_ENDPOINT` | Адрес S3-совместимого хранилища |
| `S3_ACCESS_KEY` | Ключ доступа к хранилищу |
| `S3_SECRET_KEY` | Секрет хранилища |
| `S3_BUCKET` | Имя бакета |
| `S3_REGION` | Регион хранилища |
| `MINIO_ROOT_USER` | Пользователь MinIO (если используется) |
| `MINIO_ROOT_PASSWORD` | Пароль MinIO (если используется) |
| `APP_BASE_URL` | Основной публичный адрес платформы |
| `SMTP_HOST` | SMTP-сервер |
| `SMTP_PORT` | Порт SMTP |
| `SMTP_USER` | Пользователь SMTP |
| `SMTP_PASS` | Пароль SMTP |
| `SMTP_FROM` | Адрес отправителя |
| `VAPID_EMAIL` | Контакт для web push |
| `VAPID_PUBLIC_KEY` | Публичный ключ web push |
| `VAPID_PRIVATE_KEY` | Приватный ключ web push |
| `REDIS_URL` | Redis для распределённых лимитов |
| `RATE_LIMIT_REDIS_URL` | Redis для rate limiting |
| `RATE_LIMIT_REDIS_ENABLED` | Включение Redis-лимитов |
| `RATE_LIMIT_REDIS_PREFIX` | Префикс ключей лимитов |
| `ENABLE_GUEST_ACCESS` | Гостевой доступ по умолчанию |
| `MAX_BOOK_UPLOAD_MB` | Максимальный размер загружаемой книги |
| `MAX_ACTIVE_UPLOAD_SESSIONS` | Лимит одновременных загрузок |
| `MAX_ACTIVE_UPLOAD_SESSIONS_PER_USER` | Лимит загрузок на пользователя |
| `UPLOAD_SESSION_TTL_MINUTES` | Время жизни сессии загрузки |
| `ICECAST_INTERNAL_HOST` | Внутренний адрес Icecast |
| `ICECAST_INTERNAL_PORT` | Внутренний порт Icecast |
| `ICECAST_SOURCE_PASSWORD` | Пароль источника Icecast |
| `ICECAST_ADMIN_PASSWORD` | Пароль администратора Icecast |
| `ICECAST_PUBLIC_URL` | Публичный адрес Icecast |
| `VITE_ICECAST_PUBLIC_URL` | Публичный адрес Icecast для клиента |
| `STUDIO_RECORDINGS_DIR` | Каталог записей Studio |

### 21.3. Правила работы с переменными

- Никогда не публикуйте значения секретов в документации, чатах и задачах.
- Для каждого окружения используйте отдельные секреты.
- Не переиспользуйте production-секреты в тестовом окружении.
- При компрометации меняйте секрет и перезапускайте приложение.
- Проверяйте, что публичный URL совпадает с фактическим доменом.
- Не включайте гостевой доступ, пока не настроена модерация гостевых книг.

### 21.4. Миграции базы данных

Миграции применяются вручную, по одной, в строгом порядке. Автоматического применения при деплое нет.

Правила:

- перед новой миграцией проверьте последний номер в каталоге `migrations/`;
- миграция должна быть идемпотентной;
- не используйте разрушительные операции без согласования;
- после применения проверьте повторный запуск;
- перед рискованной миграцией сделайте резервную копию.

### 21.5. Хранилище файлов

Книги, обложки, записи и награды хранятся в S3-совместимом хранилище. Если файлы не открываются:

1. Проверьте настройки S3/MinIO.
2. Проверьте права бакета.
3. Проверьте доступность хранилища.
4. Проверьте, что публичный URL сформирован правильно.

## 22. Регламенты и чек-листы

### 22.1. Ежедневный чек-лист

- Проверить **«Панель управления»**: нет ли аномалий.
- Проверить новые жалобы.
- Проверить книги и гостевые книги на модерации.
- Проверить записи эфиров, запрошенные к публикации.
- Проверить ошибки оплаты и расхождения.
- Проверить статус базы данных и сервисов.

### 22.2. Еженедельный чек-лист

- Просмотреть KPI и аналитику.
- Проверить активность клубов и клубов чтецов.
- Проверить подписки и продления.
- Проверить журнал аудита на подозрительные действия.
- Проверить, не истекли ли сроки хранения и не нужна ли очистка.
- Проверить актуальность тарифов и прав.

### 22.3. Чек-лист перед запуском

- Регистрация открыта или закрыта осознанно.
- Подтверждение email настроено.
- SMTP проверен тестовой отправкой.
- Canonical URL верный.
- Гостевой режим включён только при готовой модерации.
- Платёжный провайдер подключён и проверен тестовой оплатой.
- Тарифы активны и корректно отображаются на `/pricing`.
- Права тарифов проверены.
- Резервная копия базы данных сделана.
- Администраторы и модераторы назначены.
- Журнал аудита включён.
- Мониторинг показывает норму.

### 22.4. Чек-лист при инциденте

4. Проверьте журнал аудита.
5. Ограничьте доступ или включите режим обслуживания при необходимости.
6. Сообщите пользователям.
7. Устраните причину.
8. Проверьте восстановление.
9. Зафиксируйте выводы.

## 23. Типовые проблемы

### Пользователь не может войти

Проверьте:

- статус аккаунта;
- подтверждение email;
- блокировку;
- не истекла ли сессия;
- не сброшен ли пароль.

### Письма не приходят

Проверьте:

- включён ли SMTP;
- хост, порт, пользователя и пароль;
- адрес отправителя;
- DNS-записи;
- папку «Спам» у получателя.

### Оплата прошла, доступ не открылся

1. Проверьте платёж в **«Финансовый аудит»**.
2. Проверьте подписку в **«Подписки»**.
3. Нажмите **«Синхр.»** для повторной синхронизации.
4. Если не помогло, проверьте события провайдера и расхождения.

### Тариф не виден на `/pricing`

Проверьте:

- тип «Подписка платформы»;
- область «Вся платформа»;
- пустой ID области;
- статус «Активен»;
- видимость «Публичный»;
- наличие активной цены.

### Гостевая книга недоступна

Проверьте:

- включён ли гостевой режим;
- не истёк ли срок гостевой сессии;
- не заблокирована ли книга;
- не удалена ли книга.

### Запись эфира не видна слушателям

Проверьте:

- одобрена ли запись;
- опубликовал ли её владелец клуба;
- активна ли подписка у слушателя;
- не снята ли запись с публикации.

### Модератор не может выполнить действие

Скорее всего, действие требует роли администратора. Проверьте матрицу ролей и журнал аудита.

### Файлы не открываются

Проверьте хранилище, права бакета и публичный URL. Если проблема массовая, эскалируйте в эксплуатацию.

## 24. Словарь терминов

- **Административная панель** — интерфейс управления платформой.
- **Платформенная роль** — роль пользователя на всей платформе: пользователь, модератор, администратор.
- **Модератор** — роль с доступом к модерации контента и пользователей.
- **Имперсонация** — вход в интерфейс от имени пользователя для диагностики.
- **Аудит** — журнал административных действий.
- **Гостевая книга** — книга, загруженная в гостевом режиме.
- **Право доступа** — возможность, которая открывается после оплаты или выдачи.
- **Тариф** — продукт с ценой и набором прав.
- **Подписка** — активный доступ пользователя к тарифу.
- **Расхождение** — несоответствие в финансовой цепочке.
- **Canonical URL** — основной адрес платформы для ссылок.
- **Rate limiting** — ограничение частоты запросов.
- **Миграция** — изменение структуры базы данных.
- **S3-хранилище** — хранилище файлов.
- **Studio** — интерфейс чтеца для эфиров.
- **Запись эфира** — сохранённый аудиофайл прошедшего эфира.
